# 밍고의 보글보글 라면가게 — 아트 방향

## 원작 화면을 직접 보고 정한 것

2026-09-07 [인터플래시의 슈의 라면가게 시작 화면](https://inter87.tistory.com/156)을 열어 실제 720×574 스크린샷을 시각 확인했다. 원본 스크린샷은 검토 전용이며 이 저장소에 재배포하지 않는다. 설명은 [별도 조작 안내](https://seoulhouse1.tistory.com/19)와 함께 확인했다. 원작 SWF를 실행하거나 추출하지 않았다.

1. **큰 냄비 2×2**: 네 황금 냄비가 화면 왼쪽/중간을 차지하며, 하단은 분홍 법랑 가스레인지와 조절 손잡이로 이어진다. 우리 무대도 4:3에 네 냄비를 2×2로 배치한다. 한 줄의 작은 냄비 UI를 재사용하지 않는다.
2. **재료가 선반에 놓임**: 스프·파·면·달걀이 상단 왼쪽 칸에 직접 보인다. 카드 목록이나 같은 크기의 HTML 메뉴 버튼으로 대체하지 않고 각 재료를 그 칸에서 집는다.
3. **주전자와 쟁반의 크기**: 오른쪽 황금 주전자는 냄비보다 크고, 완성 냄비를 놓는 쟁반이 오른쪽 바깥에 있다. 물 붓기, 장갑으로 냄비 들기, 쟁반에 내리기는 각각 별도 입력 상태다.
4. **주방이 인터페이스**: 시간·수입·여분 냄비는 맨 위 몰딩에 붙어 있고, 하트/꽃무늬·식기·가구가 여백을 채운다. 바깥에 대시보드/사이드바를 만들지 않는다.
5. **끓는 때의 토핑**: 원작 안내는 물·면·스프를 먼저 넣고 물이 끓으면 파·달걀, 완성 냄비를 오른쪽 쟁반으로 옮기는 조작이다. 이 흐름을 유지하고 주문 종류·연속 팁·3일 목표를 새 규칙으로 덧붙였다. 수치가 원작과 같다고 주장하지 않는다.

## 의도적인 새 선택

- 색: 딸기 분홍 `#f65c91`, 황금 법랑 `#f4bc20`, 창문의 하늘색. 화면 속 주방 재질에서 골랐으며 웹 프레임워크 색 토큰을 사용하지 않는다.
- 글자: 자체 포함 OFL **Galmuri11**. 옛 한국 웹 게임의 선명한 작은 글자 감각을 HUD에 사용한다. 장식 제목은 같은 폰트를 크기/색/그림자만 달리한다.
- 형태: 새 플라밍고 요리사의 긴 목·깃털·흰 모자·앞치마를 크게 보여 주며, 동일 원형 머리/막대 사지 캐릭터를 가져오지 않는다.
- 재질: 냄비의 손잡이 고리·법랑 반사광·깊이 있는 안쪽, 라면 면발·스프 봉투의 접힌 끝·달걀의 껍질 광택·파의 단면을 편집 가능한 Canvas 경로로 따로 그렸다.
- 상태: 물 높이/국물/면/토핑/불/수증기/탄 흔적은 실제 냄비 상태로만 그린다. 물 붓기/재료 낙하/장갑 든 냄비 커서는 입력 이벤트와 연결한다. 셰프의 대사, 식은땀, 성공 반짝임은 실제 조리 결과에 연결한다. 배경의 셰프 몸은 정적 일러스트이며 완전한 프레임 애니메이션 캐릭터라고 주장하지 않는다.

## 자산과 권리

- `public/art/kitchen.png`: 내장 image generation으로 만든 **새** 주방/플라밍고 그림. 원작 스크린샷을 생성 입력으로 주지 않았으며 아래 텍스트 프롬프트만 사용했다.
- `src/art.js`: 냄비, 가스불, 주전자, 장갑, 설거지 스펀지, 식재료, 서빙 트레이의 직접 작성 Canvas 그림.
- `public/fonts/Galmuri11.woff2`: Galmuri11, SIL Open Font License. 동봉 `public/fonts/OFL.md` 참고.
- 사운드: 사용자가 소리를 켤 때만 생성하는 짧은 Web Audio 음. 원작 음악·음성·효과음을 가져오지 않았다.

### 생성 프롬프트

내장 imagegen, `illustration-story`, 4:3 주방 배경. 2003 한국 Flash 셀 스타일, 딸기 분홍·황금 노랑·연한 청록, 선명한 외곽선과 평면 명암. 오른쪽 위에 길고 굽은 분홍 목, 큰 눈, 깃털 머리, 흰 요리사 모자와 앞치마, 산호색 리본의 독자적 플라밍고 요리사. 왼쪽 위 빈 재료 선반, 아래쪽 비어 있는 넓은 조리대와 분홍 가구, 꽃 몰딩, 청록 창문과 줄무늬 커튼. 시간/매출용 상단 여백. 글자·로고·워터마크·버튼·게임 UI·냄비·주전자·음식·원작 캐릭터 없음. 실제 조리 기구와 상호작용은 코드로 별도 합성.

출력은 이 저장소의 위 경로에 복사해 런타임에서 사용한다. 기본 생성 디렉터리에 의존하지 않는다. 결과 그림은 요청보다 부드러운 일러스트 명암을 포함하므로 원작 벡터 도안과 동일하다고 주장하지 않는다.
